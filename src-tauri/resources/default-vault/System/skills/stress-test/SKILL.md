Use when the user asks for it ('stress test this', 'poke holes', 'devil's advocate', 'what am I missing', 'is this sound') or when the stakes warrant it without being asked: pricing, contract negotiations, hiring, team structure, a new kind of engagement, major scope, a foundation call. Not for early exploration, low-stakes reversible calls, creative work or daily routing."

# Stress test

Lead with the verdict (go, change, stop) and how reversible the call is, then the lenses. Only what applies, lopsided is fine.

- **Problem:** is it a real problem for the customer or the team, or friction the user feels because everything routes through them? Who else is affected? What evidence is there beyond one conversation?
- **Solution:** what is the simplest version that tests the hypothesis? Is it solvable without building? Is it being built because it is right, or because it is already started?
- **Opportunity cost:** what is not being done? What happens if this waits a month?
- **Failure modes:** what breaks it, what does partial success look like, what is the fallback? Name the quit conditions up front.

Add the stakeholder view (how the client, a colleague or the team will read it) when the decision touches them. Pricing advice always needs an external signal, never cost-plus alone. End with the smallest next step that tests the weakest assumption.
